# Skin Physics 基本設計書

- 文書バージョン: 1.0
- 状態: 初版（レビュー前）
- 対応要件: requirements.md 1.0
- 対象: Skin Physics

## 1. 設計方針

Skin Physics は、Soft Body と Cloth を同一シミュレーション環境で扱うGPUベースの変形物理ライブラリとする。

設計の基本方針:

1. 描画用データと物理計算用データを分離する。
2. Soft Body と Cloth は物理モデル・制約ソルバーを分離し、衝突管理を共通化する。
3. 物理計算と描画頂点への反映をGPU内で完結させる。
4. オフライン変換工程とランタイム処理を分離し、生成済み物理メッシュをキャッシュする。
5. GPU上での並列実行を前提とし、データ依存と書き込み競合を明示的に管理する。
6. 検証環境・計測機能を初期段階から整備する。
7. 実装方式はDirect3D 11 / Shader Model 5の機能制約を考慮する。

## 2. 全体構成

論理サブシステムを以下に分割する。

- Model Importer: モデル形式ごとの読み込みと共通内部表現への変換
- Physics Model Builder: 物理メッシュ、制約、対応付け、衝突用データの生成
- Asset Cache: 生成済み物理データの保存・読込
- Simulation Manager: 時間管理、シミュレーション対象管理、GPU処理の統括
- Soft Body Solver: 四面体メッシュの体積変形
- Cloth Solver: 表面メッシュの伸縮・せん断・曲げ
- Collision System: Broadphase、Narrowphase、接触応答、自己衝突
- Animation Interface: 骨格アニメーションから物理メッシュへの入力
- Render Feedback: 物理結果から描画頂点・幾何属性への反映
- Property Editor: 頂点物理特性の編集・可視化
- Test Environment: JSON試験環境、再生制御、可視化、計測

Soft Body Solver と Cloth Solver は個別の物理制約を解く。両者の相互衝突は共通 Collision System が管理する。

## 3. データ表現

### 3.1 Render Mesh

描画に必要な頂点属性、インデックス、マテリアル、スキニング情報を保持する。物理計算の都合で描画トポロジーを変更しない。

### 3.2 Physics Mesh

物理計算に用いる頂点・要素・隣接情報・物理属性を保持する。

- Soft Body: 四面体要素と境界表面
- Cloth: 三角形表面と制約トポロジー

描画メッシュと頂点数・トポロジーが異なることを許容する。

### 3.3 Collision Proxy

衝突判定の計算量を削減するための簡略形状を保持できる。描画メッシュや物理メッシュとは独立して解像度を設定できる。Proxyの利用は近似誤差を伴うため、最終接触位置の精度はNarrowphaseで補う方針とする。

### 3.4 Render Vertex Binding

物理頂点から描画頂点への対応関係を事前計算する。Soft Bodyでは四面体内の重心座標による埋め込みを候補とする。

概念データ:

```cpp
struct render_vertex_binding
{
    uint32_t tetrahedron_index;
    float barycentric[4];
};
```

描画頂点位置は対応四面体の変形後頂点位置を重心座標で補間して求める。

```
P_render = w0 * P0 + w1 * P1 + w2 * P2 + w3 * P3
```

四面体外にある描画頂点については、境界三角形への投影等による対応付けを候補とする。対応付け誤差・失敗条件は詳細設計で定義する。Clothでは描画頂点と物理頂点の対応、または補間対応を保持する。

## 4. オフライン物理メッシュ生成

### 4.1 四面体化

閉じた表面メッシュを主な入力として四面体メッシュを生成する。fTetWildをオフライン生成器の候補とし、表面前処理、四面体化、境界面回復、最適化、内部領域抽出という処理構成を参考にする。

fTetWild自体をランタイム依存にはしない。生成結果をSkin Physics独自のキャッシュ形式へ変換し、実行時はキャッシュをロードする。

採用確定前にライセンス、ビルド依存、生成品質、出力形式を確認する。

### 4.2 生成時検査

以下を検査対象とする。

- 開いた境界、非多様体、自己交差等の入力問題
- 退化四面体
- 反転四面体
- 四面体品質指標
- 元表面と生成境界の誤差
- 描画頂点との対応付け誤差

品質指標の閾値と修復方針は詳細設計で決定する。

### 4.3 キャッシュ

物理メッシュ、要素接続、隣接情報、制約、描画頂点対応、衝突Proxy等を保存する。入力モデルや生成設定が変わった場合にキャッシュを無効化できる識別情報を持たせる。

## 5. シミュレーションパイプライン

基本的なフレーム処理順序:

1. アニメーション評価
2. 物理メッシュへのアニメーション適用
3. 物理状態の予測・外力適用
4. Soft Body / Cloth の制約解決
5. 衝突候補生成と接触解決
6. 速度更新・減衰等の後処理
7. 物理結果の描画メッシュへの反映
8. 法線等の幾何属性更新
9. 描画

実際の制約解決と衝突解決の反復順序、サブステップ内の処理順序は詳細設計で確定する。全工程をGPU Compute Shader中心に構成し、通常フレームでCPUへ頂点状態を読み戻さない。

## 6. ソルバー方針

### 6.1 共通方針

XPBDを主要な制約解決フレームワークの候補とする。サブステップを用い、時間刻みや反復回数に対する剛性の安定性を確保する方向で設計する。

制約の種類・トポロジー・更新頻度に応じて、競合回避方式を使い分ける。

### 6.2 Cloth

- Stretch等の静的トポロジー制約: Graph Coloringを候補とする。
- Shear / Bend等: Gather Jacobiを候補とする。
- 自己衝突・動的接触: Gather Jacobiを候補とする。

Graph Coloringは同一色内で頂点を共有しない制約をまとめ、色ごとに順次Dispatchする。Gather Jacobiは制約ごとの補正量を独立計算し、頂点側で隣接制約の補正を収集する方式を候補とする。

### 6.3 Soft Body

四面体要素に基づく弾性変形を扱う。四面体要素の局所制約を並列評価し、頂点側で補正量を集約するGather Jacobiを候補とする。

具体的な構成モデルは未確定であり、辺長・体積制約、Shape Matching、Corotational FEM、超弾性FEM等を比較して決定する。単純な距離・体積制約をFEMと同等とみなさない。

### 6.4 Direct3D 11制約

Shader Model 5で利用可能な整数Interlocked操作を前提とし、汎用的な浮動小数点Atomic Addに依存しない。補正量の集約には、制約別出力バッファと頂点別Gather用隣接リスト等を用いる方針とする。

## 7. 衝突システム

### 7.1 対象

- Soft Body ↔ Soft Body
- Soft Body ↔ Cloth
- Cloth ↔ Cloth
- 各方式の自己衝突

デフォルトでは登録された全メッシュ組み合わせを衝突対象とする。除外設定は任意とする。

### 7.2 Broadphase

GPU Spatial Hashを主要候補とする。粒子・三角形等の衝突要素を空間セルへ登録し、近傍セルの候補を抽出する。

XPBD-Cloth等の実装を参考にGPU Radix Sortを候補とする。ただし、DX11での実装コスト、バッファ容量、GTX 1660 SUPER上の性能を評価して最終方式を決める。

Hash値だけで同一セルと判定せず、元のセル座標を保持して照合する。候補数上限を超えた場合に接触を黙って破棄しない。オーバーフロー検出・再処理・容量拡張方針を詳細設計で定義する。

### 7.3 Narrowphase

Vertex-TriangleおよびEdge-Edgeを主要な候補とする。自己衝突では隣接頂点・辺・面等の不要な組み合わせを除外する。

### 7.4 CCD

高速移動時の貫通を抑制するため、Swept AABB等で候補を絞った連続衝突判定を導入する方針とする。具体的な判定式、適用条件、接触制約への変換は詳細設計で決定する。

### 7.5 接触応答

接触は両側の物体へ作用させる。位置補正、摩擦、反発、衝突厚みを扱う。接触の対称性、質量重み付け、λ管理、摩擦モデルは詳細設計で定義する。

## 8. アニメーション連携と描画反映

アニメーション後の姿勢を物理頂点の基準状態として入力する。アニメーションによる移動・回転の慣性を考慮し、物理変形とアニメーション追従を調整できる構造とする。

Soft Bodyの描画頂点は事前生成した四面体埋め込み等で物理頂点から補間する。Clothは表面物理頂点または補間対応を利用する。

物理変形後の法線・接線等をGPUで更新する。UV・マテリアル等の非幾何属性は維持する。アニメーション速度の推定、姿勢切替時の速度処理、法線・接線の具体的な更新方式は詳細設計で決める。

## 9. 物理特性データ

メッシュ単位の基準パラメータと頂点単位のウェイトを分離する。物理方式に応じて伸縮、せん断、曲げ、体積、減衰、アニメーション追従等のチャンネルを持つ。

物理特性の意味・単位・範囲は既存OSS・論文の調査結果を踏まえて定義する。ペイントデータは描画メッシュ基準で編集し、物理メッシュへの転送結果を確認できる構成を候補とする。

## 10. 試験・デバッグ環境

試験環境は初期段階から利用可能にする。JSONで試験条件を保存し、固定時間刻み、初期状態、アニメーション、外力、衝突設定、物理特性等を再現する。

可視化対象:
- Render Mesh / Physics Mesh / Collision Proxy
- 四面体・制約・衝突候補・接触法線
- 速度・変位・体積変化
- 物理特性ヒートマップ

計測対象:
- GPU各Passの処理時間
- 制約数・接触候補数・確定接触数
- GPUメモリ使用量
- 最大変位、体積変化、静定時間等

## 11. 性能評価方針

主評価環境はGTX 1660 SUPER 6GBとし、3～40 FPSを許容範囲として品質優先で評価する。60 FPSを必須目標にしない。

性能評価では総フレーム時間だけでなく、四面体ソルバー、Clothソルバー、Broadphase、Narrowphase、接触解決、描画フィードバックの時間を個別に記録する。頂点数・要素数・制約数・接触数を変えた試験を用意する。
