# 要件定義書 初版レビュー記録

- 対象文書: docs/requirements.md 1.0
- レビュー結果: 修正後再レビューを条件に合格
- 対応版: requirements.md 1.1

## 1. 総評

目的と大枠の機能範囲は明確であり、GPU主体、Soft Body / Cloth混在、JSON試験環境、GTX 1660 SUPERを基準とする性能評価も記載されていた。一方、用語の境界、実際に検証可能な完了条件、失敗時の扱いに不足があり、実装段階で解釈が分かれるリスクがあった。

## 2. 指摘事項

| ID | 重要度 | 指摘 | 対応 |
|---|---|---|---|
| RQ-01 | 高 | 「髪束」の意味が曖昧で、ClothとStrand Hairの対象境界が不明 | Hair Cards / Hair BundlesをCloth対象と定義し、Strand Hairを初期対象外に明記 |
| RQ-02 | 高 | 3～40 FPSが対象規模・測定条件のない性能保証に見える | 開発時の許容目安とし、数値保証ではないことを明記 |
| RQ-03 | 高 | 初期貫通・候補容量超過の失敗条件が曖昧 | 最大修正量、警告・エラー、候補を黙って破棄しない要求を追加 |
| RQ-04 | 高 | アニメーション慣性の要求が目標姿勢だけで記述されている | 前回・現在の目標位置、目標速度、不連続イベントの扱いを追加 |
| RQ-05 | 高 | 完成判定が定性的で、検証方法が不明 | 初期受け入れ項目を追加し、数値閾値は詳細設計で決定する構造に変更 |
| RQ-06 | 中 | GPU処理の範囲とCPU側で許容する処理が曖昧 | 初期化・アセット構築・制御更新は許容し、毎フレーム頂点ReadbackやCPUソルバーを禁止 |
| RQ-07 | 中 | JSONの互換性・不正値・アセット識別情報が不足 | スキーマバージョン、未知バージョン検出、アセット識別情報を追加 |
| RQ-08 | 中 | 物理メッシュ再生成後のペイント転送失敗が未定義 | 対応誤差超過や曖昧な転送は警告し、自動適用しない |
| RQ-09 | 中 | 初期Importerの形式決定時期が不明 | 詳細設計開始前に初期対応形式を確定するよう明記 |

## 3. 修正確認

requirements.md 1.1に上記指摘を反映した。特に受け入れ基準を追加し、未測定の数値を合格扱いにしない方針を明確にした。

## 4. 再レビュー判定

**要件定義書1.1は基本設計の入力として合格。**

ただし、初期対応ファイル形式、具体的な数値閾値、物理モデルの材料パラメータは詳細設計で確定する。これは要件の欠落として残すのではなく、詳細設計で数値化する前提の項目として管理する。
