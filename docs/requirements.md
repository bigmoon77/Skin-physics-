# Skin Physics 要件定義書

- 文書バージョン: 1.0
- 状態: 初版
- 対象: Skin Physics
- 実装環境: Windows / C++ / Direct3D 11

## 1. 目的

Skin Physics は、ゲームキャラクターの肉体・衣服等にリアルタイムな変形物理を適用するための C++ ライブラリである。主な用途は、筋肉・脂肪・皮膚などの体積を持つ柔らかい部位と、薄い衣服・布・髪束などの表面変形を同一キャラクター上で扱うことである。

本ライブラリは学習・研究用途も兼ねるため、物理モデル、GPU処理、描画連携を検証・可視化できる構成とする。

## 2. 開発環境・制約

- OS: Windows 10 / 11、x64
- 言語: C++17 以上
- 描画・計算API: Direct3D 11 / HLSL Compute Shader
- ビルド環境: Visual Studio の .sln / .vcxproj
- 最終ランタイムに外部物理ライブラリを必須依存として持ち込まない。
- 物理シミュレーションはGPUで実行する。
- 通常フレーム処理でGPU頂点データをCPUへ読み戻さない。
- 物理結果から描画頂点への反映はGPU上で完結させる。
- CMakeを前提としない。

オフラインのメッシュ生成・変換工程で外部OSSを利用することは候補として許容する。ただし、ライセンス・依存関係を確認し、ランタイムへの依存を避ける。

## 3. 対象とする物理メッシュ

1モデルを複数のメッシュで構成でき、各メッシュは個別に物理方式・物理パラメータ・衝突設定を持つ。物理を適用しないメッシュも許可する。

### 3.1 体積メッシュ Soft Body

- 四面体メッシュを用いた体積シミュレーションを行う。
- 肉体、筋肉、脂肪、厚みのある柔軟物を主な対象とする。
- 圧縮・膨張・体積保持・局所的なへこみ・復元を表現する。
- 表面メッシュから物理用四面体メッシュを生成できる。
- 物理メッシュ解像度を調整できる。

### 3.2 表面メッシュ Cloth

- 三角形表面メッシュを用いたシミュレーションを行う。
- 薄い衣服、布、髪束等を主な対象とする。
- 伸縮、せん断、曲げ、減衰を制御できる。
- Soft Bodyと同一モデル内で併用できる。

### 3.3 混在

同一キャラクターのBody、Shirt、Pants、Hair等に異なる物理方式を割り当てられる。Soft BodyとClothは共通のシミュレーション環境に登録され、相互に衝突できる。

## 4. モデル入力・変換

- 複数のモデル形式を、形式別Importerから共通内部表現へ変換できる。
- 入力情報は頂点位置、三角形インデックス、法線、UV、スケルトン、ボーンウェイト、マテリアル、任意の頂点グループ・物理属性を想定する。
- 物理メッシュと描画メッシュの頂点数・トポロジーが異なる構成を許容する。
- 物理メッシュ生成結果をキャッシュし、実行時に再生成せずロードできる。
- 不正な入力、生成失敗、対応付け失敗を検出し、原因を報告する。

対応する具体的なファイル形式は設計段階で決定する。

## 5. アニメーションと物理の連携

処理の基本順序は次の通りとする。

1. スケルトンアニメーションを評価する。
2. アニメーション結果を物理頂点へ適用する。
3. アニメーションを基準状態として物理シミュレーションを実行する。
4. 物理変形結果を描画メッシュへ反映する。
5. 描画する。

- 骨格アニメーションと物理変形を併用できる。
- 骨格の移動・回転による慣性を扱える。
- アニメーション追従と物理変形の影響度を調整できる。
- 描画メッシュのUV、マテリアル等、変形対象外の属性を維持する。
- 変形後の法線等の幾何属性を更新する。
- GPU内で処理を完結させる。

## 6. 衝突・自己衝突

- Soft Body同士、Cloth同士、Soft BodyとClothの相互衝突をサポートする。
- 各メッシュの自己衝突をサポートする。
- 初期状態でのメッシュ間貫通を検出し、可能な範囲で自動修正する。修正不能な場合は警告・エラーを報告する。
- 衣服と身体の貫通、自己交差を可能な限り抑制する。
- 高速移動時の貫通を抑制するため、連続衝突判定または同等の対策を検討する。
- 接触応答は双方の物体へ作用する。
- 衝突厚み、摩擦、反発等を設定できる。
- 全メッシュ組み合わせの衝突をデフォルトで有効とし、必要に応じてメッシュ単位の除外設定を行える。
- 総当たりの全頂点・全三角形比較を主方式にしない。

## 7. 物理特性・編集

メッシュ単位および頂点単位で物理特性を調整できる。

想定する特性:
- 伸縮剛性
- せん断剛性
- 曲げ剛性
- 体積剛性
- 減衰
- アニメーション追従剛性

物理方式に応じて適切な特性を使用する。値の意味・単位・範囲は、既存の物理ライブラリや論文を参考に設計段階で決定する。

### 7.1 ペイント編集

- 頂点へブラシで物理特性を塗布できる。
- ブラシ半径、強度、目標値、対象チャンネルを設定できる。
- 既存値から目標値へ強度に応じて段階的に近づける編集を基本とする。
- 平滑化、平均化、消去等の編集機能を検討する。
- ヒートマップで値を可視化できる。
- 描画メッシュ上で編集した値を物理メッシュへ転送できる。
- 物理メッシュ再生成後も編集データを再利用できる。
- 編集データを保存・読込できる。

## 8. シミュレーション制御・検証環境

検証用のシミュレーション環境を用意する。

- 再生、停止、一時停止、リセット
- 1フレーム進行
- 時間倍率・スローモーション
- 重力変更
- 任意位置・方向・強度・半径・継続時間を持つ外力・衝撃
- スケルトンアニメーションとの同時再生
- 四面体、表面メッシュ、制約、衝突形状、速度、体積変化、物理特性の可視化
- GPU処理時間、シミュレーション時間、最大変位、収束・静定時間等の計測
- 同じ初期条件からの繰り返し試験と結果比較

検証環境は物理機能の完成後に追加するのではなく、初期段階から利用できるようにする。

## 9. JSONによる試験環境保存

試験条件は人間およびChatGPTが編集可能な可読性の高いJSONで保存・読込できる。

保存対象:
- シミュレーション設定、固定時間刻み、サブステップ、反復回数
- 重力、初期姿勢・状態
- アニメーションクリップ、再生時刻、速度
- 外力・衝撃の位置、方向、強度、継続時間
- 衝突設定、対象オブジェクト
- 物理特性・頂点ウェイト
- 試験開始・終了条件、リセット条件
- 乱数を使用する場合のSeed

同一環境で試験条件を再現できること。GPUやハードウェア差による浮動小数点演算の差を考慮し、異なる環境間での完全なビット一致は必須としない。必要に応じて許容誤差を定義する。

## 10. 性能・品質目標

- 主な評価GPU: NVIDIA GeForce GTX 1660 SUPER 6GB
- 想定用途: 1体の描画キャラクターを中心としたリアルタイム変形。別途、衝突専用オブジェクトを配置できる。
- 目標フレームレートの許容範囲: 3～40 FPS。
- 品質を優先し、60 FPS達成を必須条件にしない。
- ただし、品質向上に対する計算量・メモリ使用量を計測可能にする。
- GPU処理を基本とし、通常フレームでのCPU読み戻しを避ける。
- 衝突候補数、制約数、GPUメモリ、各処理段階のGPU時間を計測する。

## 11. 対象外・未確定事項

- 最終ランタイムに外部物理ライブラリを組み込むこと。
- CPU主体の物理シミュレーション。
- 全てのモデル形式への対応を初期段階で保証すること。
- 異なるGPU間での完全なビット単位決定性。
- Soft Bodyの構成モデル、Clothの具体的な制約式、衝突アルゴリズム、Broadphase構造、容量上限等は基本設計・詳細設計で決定する。

## 12. 開発工程の原則

要件定義、基本設計、詳細設計、レビューを順に行い、レビュー通過後に実装へ進む。設計変更は文書へ反映し、バージョン履歴を残す。実装開始前に設計上の未決定事項と受け入れ条件を明確にする。
